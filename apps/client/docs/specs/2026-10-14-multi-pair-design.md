# 큐브 여러 개 한 번에 등록 설계

날짜: 2026-10-14 · 상태: 검토 중

## 목적

장치 추가에서 켜 둔 큐브 여러 개를 한 흐름으로 등록한다. 실제 제품 흐름이다(HW · SW 모두).
여러 개를 한꺼번에 등록하면 어느 실물 큐브가 어느 슬롯(A~F)인지 알 수 없으므로, **큐브를 하나씩 패드 확인점에 올린 순서**로 슬롯을 정한다. 올리는 순간 core가 자동으로 감지해 등록한다.

## 결정

| 항목           | 선택                                       | 이유                                                        |
| -------------- | ------------------------------------------ | ----------------------------------------------------------- |
| 짝짓기 방식    | 확인점에 올린 순서대로 다음 빈 슬롯        | 손에 든 실물과 글자가 바로 짝지어진다. LED 명령이 필요 없다 |
| 감지           | core가 자동(버튼 없음)                     | 미등록 큐브 자리는 core(padLink)만 안다                     |
| 등록 개수      | 시작할 때 미등록 큐브 수, 빈 슬롯 수까지   |                                                             |
| 진행 상태      | 스냅샷 `pairing`                           | 설정 · 페어링 화면 어디서 보든 같다                         |
| `registerCube` | 지운다                                     | 쓰는 곳이 이 흐름뿐                                         |
| 가짜 찾기 단계 | 지운다(2.2초 찾는 중 · "이 큐브 등록하기") | 미등록 큐브 목록은 패드가 이미 알려 준다                    |

## 인터페이스(`packages/protocol`)

- `Snapshot.pairing: { total: number; done: Slot[] } | null` — 등록 중일 때만 값이 있다. `done`은 이번 흐름에서 등록한 슬롯(순서대로). 처음 값 `null`.
- `CubeSpaceApi`
  - `startPairing(): Promise<number>` — 미등록 큐브 수(빈 슬롯 수까지)를 돌려준다. 0이면 pairing을 시작하지 않는다(`null` 그대로). 이미 pairing 중이면 새로 센다.
  - `stopPairing(): Promise<void>` — `pairing = null`. 이미 등록한 큐브는 남는다.
  - `registerCube()` 삭제.
- `PAD_CHECK = { xy: [PAD_W / 2, PAD_H / 2], r: 20 }`(mm) — 확인점. 패드 가운데, 반경은 큐브 한 변(35 mm)보다 조금 크게.

## core

- 등록 판정 `tryPair()`: pairing 중이고 `done.length < total`이면, 패드가 아는 큐브 중 **미등록 · 무선 연결 · 확인점 안**(가운데와 거리 ≤ r)인 것 하나를 가장 앞 빈 슬롯에 등록하고 `done`에 슬롯을 더한다.
  - 큐브를 만드는 코드(이름 = 슬롯 알파벳, 기본값)는 지금 `registerCube` 것을 그대로 옮긴다.
  - 이미 등록된 큐브는 후보가 아니므로, 등록 직후 큐브를 내리지 않아도 다시 등록되지 않는다.
- 판정 시점: `startPairing` 직후(이미 올려 둔 큐브), padLink가 `cube` · `sync`를 받은 뒤.
- 다 마친 뒤(`done.length === total`)에는 더 등록하지 않는다. `pairing`은 화면이 `stopPairing`할 때까지 남는다(완료 표시용).
- 패드 연결이 끊기면(padLink `onClose`) `pairing = null`.

## 화면(`apps/client`)

- `usePairing`: 단계 = `idle` · `place`(pairing 진행 중) · `done`(다 마침) · `none`(찾은 큐브 0개). 스냅샷 `pairing`에서 단계를 읽는다.
  - 시작: `startPairing()` → 0이면 `none`(1.7초 뒤 `idle`).
  - `done`이면 1.7초 뒤 `stopPairing()` → `idle`.
  - 그만하기: `stopPairing()`.
  - 등록될 때마다 기존 `onRegistered(slot)`을 부른다(`done`에 새로 생긴 슬롯).
- `PairPanel` 문구
  - `place`: "큐브 하나를 확인점에 올려 주세요 (k/N)". 하나라도 등록했으면 "{글자}로 등록했어요 · 내리고 다음 큐브를 올려 주세요 (k/N)". 버튼 "그만하기".
  - `done`: "큐브 N개 등록 완료".
  - `none`: "찾은 큐브가 없어요 · 등록할 큐브를 켜 주세요".
  - 단계 막대 3칸(패드 연결 → 큐브 등록 → 위치 확인)은 그대로: `place` · `done`은 3단계.
- `PairingScreen` 안내 "등록할 큐브를 한 번에 하나씩 켜 주세요" → "등록할 큐브를 모두 켜 주세요".
- 테스트 대역 `test/fakeApi.ts`: `startPairing` · `stopPairing`을 흉내 낸다(등록은 테스트가 스냅샷을 바꿔 흉내).

## 테스트

- core(`apps/core/test`)
  - `startPairing`: 미등록 수를 돌려준다 · 빈 슬롯 수까지만 · 0이면 `pairing` null.
  - 확인점 안으로 `cube`가 오면 등록, 밖이면 안 함. 무선 끊긴 큐브는 안 함.
  - 시작 전에 이미 확인점에 있던 큐브는 시작 직후 등록.
  - 등록된 큐브를 다시 올려도 무시 · `total`을 채운 뒤에는 더 등록 안 함.
  - `stopPairing` · 패드 끊김 → `pairing` null.
- client: PairPanel(설정 · 페어링 화면) 테스트를 새 흐름으로 — k/N 표시, 등록 후 문구, 완료, 0개 안내, 그만하기.
- 손으로(SW): pad-sim stdin `move A2:F0 100 66` 또는 시뮬레이션 화면에서 확인점으로 끌기 → 설정의 장치 추가가 1/4 → 2/4로 넘어간다.

## 범위 밖

- 큐브 LED로 등록한 글자 보여 주기(LED 명령이 core에 아직 없다)
- 확인점을 패드 그림 위에 표시하기
- 위치 보정(센서 보정값) — 지금 확인점은 짝짓기용이다
